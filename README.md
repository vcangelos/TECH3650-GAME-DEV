## Development Process

We use Agile practices to divide development into manageable tasks, build working features, test results, and revise our priorities.

For Project 1, our worksheet’s sprint backlog records each task’s owner, priority, status, and definition of done. During stand-ups, we discuss completed work, current work, blockers, and the next checkpoint.

A task is complete when its intended behavior has been implemented, tested, and documented.

## Testing and Iteration

Our testing covers:

- **Functional testing:** Do individual mechanics work?
- **Usability testing:** Can a player understand the game without developer coaching?
- **Boundary testing:** What happens with repeated interactions or unexpected actions?
- **Regression testing:** Do existing features still work after a change?
- **Published-build testing:** Can the intended player access and play the released version?

Before the Project 1 release, we verify that the complete gameplay loop works **three consecutive times**.
